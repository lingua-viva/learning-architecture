## 1. Module — `src/lingua_viva/docpipe/sync.py` (T6-owned)

Queue file: `<vault>/sync/queue.json` (contracts §1) — a JSON list of entries:

```json
{
  "entry_id": "SYN-<uuid>",
  "student_id": "student-...",
  "enqueued_at": "2026-08-04T...Z",
  "attempts": 0,
  "last_attempt_at": null,
  "last_error": null,
  "status": "pending" | "pushed",
  "pushed_at": null,
  "destination_ref": "lens-exports"
}
```

API:
- `enqueue_lens(student_id, *, root=None, destination_ref="lens-exports") -> dict`
  — appends (deduping: an existing PENDING entry for the same student is
  refreshed, not duplicated — one student, one pending sync). Written through
  the vault-owned queue path atomically. T5's save path calls this.
- `drain(*, root=None, now=None, push=None) -> dict` — one worker pass:
  for each pending entry whose backoff window has elapsed, render the lens
  (§2), call `push` (default `drive.push_file`) with the rendered file, mark
  `pushed` on success, record `attempts += 1` + `last_error` on failure.
  Returns `{"pushed": n, "pending": n, "failed_this_pass": n}`. Never raises
  for per-entry failures.
- `sync_status(student_id=None, *, root=None) -> dict` — per-lens or overall:
  `{"status": synced|pending|failed, "attempts", "last_error", ...}`.
  `failed` = pending with `attempts >= 3` (still retried, but surfaced).
- `start_worker(interval_seconds=60)` / `stop_worker()` — thread-based loop
  calling `drain` (daemon thread; the caller wires it at app startup — that
  wiring is T5-or-later's line in web.py, not this module's).

**Retry/backoff:** exponential — attempt n waits `min(2^n, 30)` minutes before
the next try; `now` injectable for tests. Offline for a day = queue intact,
drains when connectivity returns.

**Offline safety:** the queue is plain JSON written atomically via the vault's
temp+replace pattern; kill mid-drain → entry still pending (status only
flips AFTER a successful push); restart → `drain` picks it up. No entry is
ever dropped; duplicates are prevented by the per-student pending dedupe and
by marking `pushed` only on confirmed success.

**Conflict policy (two teachers, same student):** last-write-wins is wrong for
shared student records. The exported artifact is named
`lens-<student_id>-<teacher-label>-<timestamp>` — per-teacher, timestamped
exports that never overwrite another teacher's file. Merging stays where it
belongs: evidence[] is additive by design, and the authoritative merge is the
local lens engine ingesting the other teacher's export as a source (existing
Drive-import path), not a blind file overwrite in Drive. Day one: no
overwrites possible, full history visible in the folder.

## 2. Human-readable rendering

`render_lens_markdown(lens_data) -> str` — a teacher-readable Markdown
document (Drive renders .md; a Google-Doc conversion is a T1/push_file
option later): display name, updated-at, then each populated profile
category as a section with its values and an evidence line per item
("evidence: document SRC-… span SPN-… / observation OBS-…, added by …").
Empty categories listed under "No evidence yet" — honest, never invented.
The rendered file is written to `<vault>/sync/outbox/<filename>.md` and that
path is what `push_file` ships.

## 3. Privacy

Lens content is student PII going to the teacher's OWN authorized Drive —
the intended shared-visibility channel (prompt ruling). It never touches an
LLM. `drain` logs `drive_upload_shared` (existing privacy-event name) per
successful push; the egress class stays visibly distinct from model calls in
both code and logs.

## 4. Tests (tests/test_docpipe_sync.py)

1. enqueue → queue.json valid, pending_count in manifest reflects it.
2. enqueue twice same student → one pending entry (refreshed, not duped).
3. drain with fake push → pushed, correct rendered content (markdown contains
   display name, populated category, evidence line, no invented fields).
4. drain with failing push → attempts+1, last_error recorded, still pending;
   backoff respected (immediate second drain skips it; time-travel `now`
   retries it).
5. Kill-mid-queue simulation: entry pending → new process (fresh import)
   drain → pushed exactly once, no duplicates.
6. push seam raising NotImplementedError (current reality) → pending with
   honest reason, drain returns without raising.
7. sync_status per lens: synced / pending / failed transitions.
8. Rendered markdown for a lens with an empty category shows it under "No
   evidence yet".
